# AML-S0009 — Amlogic P1 FIP packaging + TF-A FIP header

## What it is
Coordinator-supplied primary references (Codex research, 2026-10-09), independently
re-verified by Claude against `bootloader.img`:
- **Amlogic P1 `fip/p1/build.sh`** (pinned commit `85456d35…`): the outer
  packing + `create-device-fip` inputs + DDR boot-blob packaging. Uses the same
  5 tags and **16-byte descriptors `{tag, LE u32 offset, LE u32 size, u32
  reserved}`** (the reserved-word interpretation, not LE-u64-size). **P1 is NOT
  an S7D spec**: P1 writes container version 1; coffey is version 2 with a
  different build-field layout — do not run a v1 parser blindly.
- **TF-A `firmware_image_package.h`**: FIP ToC header magic `0xaa640001` and the
  standard SCP_BL2/BL31/BL32/BL33 UUID bytes. Initially retrieved from moving master; now independently matched at TF-A
  v2.10 commit `b6c0948400594e3cc4dbb5a4ef04b815d2675808` (2026-10-09).
  This identifies standard UUIDs, not the shipped ATF version.

## What it establishes
The structure/naming grammar of coffey's bootloader container (AML-F0010/F0016).
`related-family` for P1 (different platform/version); the authoritative evidence
is coffey's own bytes (verified in-image), with these sources naming the fields.

## Credibility note
`primary` sources; scope `related-family` (P1 = different Amlogic platform/version;
TF-A = generic). coffey-exact facts come from the in-image parse, not from
assuming P1/TF-A describe coffey unchanged.

## S7D packaging follow-up — 2026-10-09
The P1 analogy is supplemented by S7D-specific primary source at Khadas U-Boot
commit `ee291cdb50ce050e22fdaa203d039eefdf3cc0f2`:
[build.sh](https://github.com/khadas/u-boot/blob/ee291cdb50ce050e22fdaa203d039eefdf3cc0f2/fip/s7d/build.sh),
[sign-blx.sh](https://github.com/khadas/u-boot/blob/ee291cdb50ce050e22fdaa203d039eefdf3cc0f2/fip/s7d/bin/sign-blx.sh),
[gen-boot-blobs.sh](https://github.com/khadas/u-boot/blob/ee291cdb50ce050e22fdaa203d039eefdf3cc0f2/fip/s7d/bin/gen-boot-blobs.sh).
These trace DDR data through a merged BL2-associated CSINIT input and permit an
empty outer DDRF slot. Exact Coffey localization remains unresolved.
The S7D/S905X5M device-fip-header template matches the vendor UUID and size,
strengthening probable BL40 identification. It does not identify payload code.
Source file hashes are retained in Codex source-followup-hashes.json and
soc-id-source-artifact-hashes.json. No vendor packer/key/tool was executed.
