# AML-S0008 — mainline Linux S7D DT + drivers (L2) and CoreELEC vendor UART driver (L3)

## What it is
Upstream torvalds/linux S7D platform support at pinned commit `af32da41…`:
- `amlogic-s7d.dtsi` (sha256 `d3390720…`) — mainline S7D SoC DT (L2).
- `amlogic-s7d-s905x5m-bm202.dts` (`57cfa302…`) — mainline BM202 **development
  board** DT (2 GiB, dev-board model string).
- `meson_uart.c` (`eb3cd554…`) — mainline UART driver (matches `meson-s4-uart`).
- `meson-gx-socinfo.c` (`515fa88f…`) — SoC-ID driver (`S7D`=0x47 via AO_SEC_SD_CFG8).
Plus the CoreELEC vendor UART driver `meson_uart.c` (`23d5647d…`) at commit
`8646fbd1…` (L3) for the vendor-vs-mainline comparison. Fetched PC-side via
raw.githubusercontent (passive source, not firmware).

## What it establishes
The mainline (L2) and vendor (L3) driver/DT layers for S7D, enabling the
three-layer comparison (shipped DTB L1 = AML-S0005). Backs AML-E0006 / AML-F0011.
The mainline BM202 is explicitly a **development board** — its memory/peripheral
enablement must not be presumed to describe retail coffey.

## Credibility / scope note
`primary` (actual upstream + vendor source). Scope `exact-soc` (S7D); mainline
support is generic-S7D, coffey ships the CoreELEC vendor stack — the two diverge
(UART binding/clock-names/driver), which is the point of the comparison.
