# AML-S0001 — onn 4K Plus (coffey) on-device identification

## What it is
Direct on-device readout of the owner's own onn 4K Plus ("coffey"), over adb on
hardware we own: Android `getprop` build properties and the kernel's own
`/proc/config.gz`.

## Traceable observation (reproducible, read-only)
Each inventory field in `AML-F0001` traces to a specific property/symbol. To
reproduce: `adb shell getprop` and `adb shell zcat /proc/config.gz`.

| Inventory field | Observable | Source command/key |
|---|---|---|
| Marketing name / codename | device/platform id | `ro.product.*.device`, `ro.board.platform` |
| SoC | Amlogic part | `ro.board.platform` + kernel DT/model |
| CPU / arch | 64-bit kernel, 32-bit userland | `ro.product.cpu.abilist`, `uname -m` |
| Android version | 14 | `ro.build.version.release` |
| Security patch level | 2026-03 | `ro.build.version.security_patch` |
| Kernel version | 5.15.196-android14-11 | `uname -r` / `/proc/version` |
| Bootloader state | locked, AVB green | `ro.boot.verifiedbootstate`, `ro.boot.flash.locked`, OEM-unlock toggle state |

Raw dumps are **not** committed (they can carry identifiers; repo `.gitignore`
blocks `settings_*`, `dumpsys_*`, `raw/`). This record states the field→key
mapping, not the raw output.

## What it establishes
The device's identity — SoC line, kernel version/arch, Android version,
security patch level, and bootloader lock state — settled on the device
itself. It does **not** establish board revision or exact firmware build id
(those remain `unknown` in `AML-F0001`).

## Credibility note
`primary` — values come from the device's own build properties and kernel
config, not a spec sheet, retail listing, or aggregator. A published narrative
summary appears in `../../../research/root-study.md` (secondary to this
