## Factory tool

`com.gretzky.hwinfo` ("HardwareInfo" 4.18.26, `/system/app/HardwareInfo`), running as `android.uid.system`.

- It contains upload endpoints for the factory's manufacturing-execution systems (MES): device info by MAC,
  test logs, serial-number lookup. It also has mic, Wi-Fi-scan and MAC test code.
- Its sticky service `StartTempService` is restarted by the system when killed. **Retail-mode behavior observed in code:**
  it mirrors the developer USB-debugging toggle into a u-boot variable (`otg_device`) and checks the remote-pairing app.
- The factory flow is **gated**: a test-state file in the app's private storage, or a `FactoryTester_signed.apk` on a
  mounted USB drive (priority-1000 `MEDIA_MOUNTED` receiver) that triggers a self-update. `sys.factorytool.running` is unset.
- **Assessment:** dormant on retail units. The USB-triggered update path inside a system-UID app is attack surface,
  probably limited by Android's same-signer rule. *Pending: boot-state log line (scenario F), and disclosure decision.*

Other vendor apps running as the system UID: `com.gretzky.GlobalKey`, `com.onn.updatenotification`,
`com.onn.bluetoothconnect`, `com.droidlogic`, `com.droidlogic.tv.settings`, `com.droidlogic.mictoggle`,
`com.droidlogic.android.tv.connecteddevices`, `com.netflix.tokenmanager`.
